01

How a job works

The logic lives in scripts. A GitHub Action only decides when a script runs and hands it the secrets, so every job also runs on a laptop, dry, and prints what it would write. This is how the three live workflows work today.

  1. Schedule

    A workflow starts on its timer, on a Run button, or on a pull request, where it is always dry.

  2. Read

    The script reads the chain or the service through that chain family's own library.

  3. Compare

    It sets what it read beside what Notion holds, and beside the list of cases already decided.

  4. Check, then write

    A value that differs and passes its check (a number in range, a real date, a text of the row's own shape, two sources agreeing) is written to Notion, plain text. One that fails, or that needs a key or a form, goes in the email.

  5. The site

    The pages read Notion when they render, so the site follows once Super refetches the page. No paste, no release, nothing fetched in the browser.

Writes

Whatever a script can read, it writes

The job changes Notion itself, only where the value differs and only after its check.

  • Reward rate with its date
  • Commission, unbonding, slashing, status
  • Our votes and the release-borne proposals
  • Read minutes, guide steps, social cards
  • Dashboard status, repo visibility
  • The typed fallbacks and counts
Reports

What needs a key, a form or a judgement

In the run's issue every time; in one email only when it has drifted.

  • Profiles on other people's registries and chains
  • The Discord invite
  • Dead links
  • Wallet screenshots
  • A post's author
Watches

What is not site data

An email at once. Nothing on the site depends on them.

  • Avalanche's delegation room
  • Unclaimed rewards
  • A validator jailed or inactive

Only rows marked Auto are written

A Rate source choice on each network. Mina, EigenCloud and Sommelier stay Manual.

A sanity band

A new rate more than a third away from the current one is held back and flagged.

A decisions list

Each chain's accepted history, such as Gravity Bridge shown as 0. A writer follows it and reports only what is new.

A history file

One line per chain per run, so any figure on the site can be traced to the day it was read.

One issue a run, one email on drift

The run's log says "12 written, 2 held back". Every run opens an issue in the private repo with before and after for each write and the list left for a hand; an email goes out only when that list is not empty or the run failed.

One writer at a time

Jobs queue for Notion, write plain text only, and stay under its three requests a second.
